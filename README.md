# Личная CRM

Приложение для своих контактов: кто это, откуда знакомы, как связаться, о чём договорились.
Подробнее — `specs/01-продуктовая-идея.md`.

## Что нужно на компьютере

- Node.js 24 (LTS) и pnpm
- Docker Desktop — в нём работает база данных PostgreSQL

## Настройки подключения

Пароль и адрес базы лежат в файле `.env` в корне проекта. В git он не попадает.

Если `.env` нет (например, проект скачан заново):

1. Скопируйте `.env.example` в `.env`.
2. Заполните значения: имя пользователя, пароль, имя базы, порт (обычно `5432`).
3. Соберите из них строку `DATABASE_URL` по образцу из `.env.example`.

## База данных

Все команды — в терминале, в папке проекта.

Запустить базу:

```sh
docker compose up -d
```

Проверить, что база работает (в колонке STATUS должно быть `healthy`):

```sh
docker compose ps
```

Остановить базу (данные сохранятся):

```sh
docker compose stop
```

База запускается сама вместе с Docker Desktop, пока её не остановили вручную.

Данные хранятся в Docker-томе `personal-crm_db-data` и переживают перезапуск компьютера и контейнера.
Команда `docker compose down -v` **удаляет все данные базы** — не запускайте её, если данные нужны.

## Первый запуск

Все команды — в терминале, в папке проекта, по порядку:

```sh
pnpm install        # поставить библиотеки
docker compose up -d # запустить базу
pnpm db:migrate     # создать таблицы в базе
pnpm db:seed        # (по желанию) добавить 1000 тестовых контактов
pnpm dev            # запустить приложение
```

Затем откройте в браузере http://localhost:3000.

`pnpm db:seed` добавляет контакты только в **пустую** базу. Если контакты уже есть, команда ничего не меняет.
Другое количество: `pnpm db:seed 200`.

Примерно у 3% тестовых контактов задано, как часто общаться. С частью из них давно не общались — они сразу видны на главной в блоке «Пора связаться».

В тестовых данных также есть шесть групп (Семья, Друзья, Знакомые, Коллеги, Теннис, Аналитики), и примерно половина контактов состоит в одной или нескольких из них.

## Обычный запуск

```sh
pnpm dev
```

Приложение открывается на http://localhost:3000. Остановить — `Ctrl + C` в терминале, где оно запущено.

Приложение доступно только с этого компьютера: с телефона или другого компьютера в той же сети оно не откроется.
Так сделано специально — входа по паролю нет, и иначе контакты увидел бы любой в той же Wi-Fi-сети.

## Как проверить руками

1. Откройте http://localhost:3000 — виден список всех контактов, сверху их количество.
2. Нажмите «Добавить контакт», заполните имя, нажмите «Добавить контакт» — контакт появится в списке (выделен лаймовой рамкой, с пометкой «Новый»).
3. Начните вводить имя в поиске — список сократится до подходящих людей.
4. Откройте контакт, допишите заметку в поле «Заметки», нажмите «Сохранить» (или `Ctrl + Enter` / `⌘ + Enter`).
5. Обновите страницу — заметка на месте.
6. Откройте тот же адрес в другом браузере (например, Safari, если работали в Chrome) — те же контакты и та же заметка.
7. В карточке контакта внизу нажмите «Удалить контакт» и подтвердите — появится «Контакт удалён», и вы вернётесь к списку (или к результатам поиска). Контакта больше нет в списке, количество сверху уменьшилось на один. Удаление насовсем, вернуть контакт нельзя.
8. Нажмите «Группы» в шапке — откроется страница со списком групп и числом людей в каждой. Впишите название в поле «Новая группа» и нажмите «Создать» — группа появится в списке.
9. В карточке любого контакта, в поле «Группы», отметьте одну-две группы и нажмите «Сохранить» — метки выделятся, а в общем списке на главной под именем контакта появятся эти метки.
10. На главной нажмите на название группы под поиском — список сократится до людей из этой группы.

## Автоматическая проверка

```sh
pnpm test
```

Проверяет отдельные функции приложения (например, поиск и сортировку контактов) на настоящей базе данных.
Нужна запущенная база (`docker compose up -d`). Команда работает в своей базе рядом с основной — с суффиксом `_test`,
пересоздаёт её перед прогоном и очищает между тестами. Ваши контакты не трогает.

```sh
pnpm test:e2e
```

Проходит главный сценарий из `specs/01-продуктовая-идея.md` в Google Chrome без окна браузера: список, добавление, поиск, заметка, «другой браузер».
Ваши контакты не трогает: создаёт рядом отдельную временную базу (с суффиксом `_e2e`) и удаляет её в конце.
Нужны запущенная база и установленный Google Chrome; занимает около минуты.

## Другие команды

- `pnpm lint` — проверка кода
- `pnpm typecheck` — проверка типов
- `pnpm db:generate` — создать миграцию после изменения схемы в `src/db/schema.ts`, затем `pnpm db:migrate`

## Выкатка на сервер

Новая версия выкатывается сама: после `git push` в ветку `main` GitHub собирает приложение и ставит его на сервер.
Ход выкатки виден на GitHub во вкладке Actions репозитория: зелёная галочка — версия на сервере, красный крестик — что-то не так.
Выкатить ещё раз без изменений в коде: Actions → Deploy → кнопка Run workflow.

Что происходит (`.github/workflows/deploy.yml`):

1. GitHub собирает приложение в Docker-образ (`Dockerfile`).
2. Отправляет образ на сервер по ключу деплоя. Ключ умеет только две вещи — загрузить образ и переключить версию (`deploy/crm-deploy.sh`); зайти с ним на сервер и выполнить что-то другое нельзя.
3. На сервере применяет миграции базы, запускает новую версию и проверяет адрес `/health`. Если новая версия не отвечает — возвращает прежнюю, а выкатка на GitHub помечается красным.

На сервере всё лежит в папке `/opt/personal-crm`: `compose.yml` (приложение и его база в Docker) и `.env` (пароль базы, образец — `deploy/.env.example`).
База на сервере своя, с базой на этом компьютере не связана.

Файлы из папки `deploy/` на сервер сами не попадают — ключ деплоя специально не может их менять. Если они изменились, их переносят на сервер вручную.

Приложение на сервере: https://app.myfirstcrm.site. Входа по паролю пока нет — адрес открыт всем, кто его знает,
поэтому там только сгенерированные тестовые контакты.
